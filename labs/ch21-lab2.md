# Lab 21.2 — Generic or Yours?

| Field | Value |
|---|---|
| Type | Check It (optional, at home) |
| Objectives | Ch. 21 O1, O3 (LO7, LO5) · tags 4D:DISC, 4D:DIL |
| Time | 20 minutes |
| Materials | The provided sample sheet: a "code of AI ethics for students" produced by an AI model, with the model name and the date of generation (instructor package, course site). Optional: a tool your institution provides or approves (for example, an enterprise chat assistant with data protection) to generate your own sample, with no personal data |

## Steps (tool-neutral)
1. Read the sample code. Count its lines.
2. Mark each line with one of the kinds in section 21.1: **policy restatement** (a rule someone else sets, copied in), **professional code**, **slogan** (a good intention with no moment or action), **dated tool note**, or **commitment** (a moment, an action, a reason).
3. Apply the trigger test (section 21.2) to every line marked "commitment": moment, action you or someone else can trace, reason with evidence. Count how many pass all three.
4. Pick one line that fails and rewrite it from your own evidence (a Failure Diary entry, an assignment result, a lab record), as section 21.2 shows.
5. Write two sentences: what the sample does well, and what no generated code can supply.

If you generate your own sample, record the tool, the model name if shown, the date and your exact prompt, and use no personal information.

## Expected observations
Generated codes of this kind tend to be lists of slogans ("be transparent," "use AI responsibly") with few lines that name a moment or a traceable action, and no line can point to your own evidence, because the tool has none. Expect zero or very few lines to pass all three questions. A generated list can still suggest topics you had not thought of.

## Debrief
1. Why can a generated code never pass the reason question for you? (analyze)
2. If you adopt an idea from the sample, what must you do before it goes into your code? (apply)

## Deliverable and rubric
None (optional practice). Nothing from the generated text goes into your code as is; an idea you adopt is rewritten in your own words, passes the test, and is listed in your code's declaration. Lab notes in Appendix E.

## Accessibility and alternatives
The sample sheet is available as an accessible document. The lab works fully on paper with the provided sheet; no AI account is needed.

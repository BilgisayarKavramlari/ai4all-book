**Fresh, temporary chat.** Every run starts a new conversation, so no earlier messages are in the context. Where the tool offers a temporary or private mode that is not saved to memory (a product feature that saves notes about a user, or draws on past chats, and adds them to later conversations), use it. Current steps for each tool are in Compass.

## Steps (tool-neutral)
1. **Briefing (10 min).** Open the log template. Your instructor pairs you for the peer swap. If you have no task of your own, pick one from the task bank. No personal or confidential data, yours or anyone else's.
2. **Frame (10 min).** Write your frame card (the Your Turns in sections 5.1 and 5.2 are done here): goal, audience, 3–5 checkable success criteria, limits, what stays with you, and a rung (or the floor) for each part of the task with one reason. A teammate reads your criteria and marks any they could not score; rewrite those.
3. **Versions 1–3 (20 min).** Write v1 from your frame card (an honest first attempt). Run it once in a fresh, temporary chat and score the output against each criterion (met, partly, not met). Write v2 and v3: one change each, naming the prompt part (role, task, context, constraints, in-context examples, output format) or "frame", with a prediction written before the run. One run each in class.
4. **Peer swap (15 min).** Run your partner's v3 in a fresh chat without asking them anything. Score the output against their criteria. Tell them what seemed to be missing from the prompt. **This swap counts as the A3 peer swap**: each of you records what it revealed and the change it led to. Swapping your final prompt again is optional.
5. **Share and critique (15 min).** Each team shows the one change that mattered most and one that did not.
6. **Exit (5 min).** Finish the sentence: "My prompt works for … but I have not tested …"

At home (A3, about 60–70 minutes): second runs of v1–v3, v4 (one change) with two runs, one run each on a different and an edge input, the verification note (recompute every total; compare each fact with your source, textbook or course notes), the reflection and the AI Use Declaration.

## Expected observations
Most v1 prompts miss at least one criterion because something in the frame card never reached the prompt. Many students change several things at once in v2; the log makes that visible. The peer swap usually finds one assumption (an audience, a period, a term) that the owner could not see.

## If it does not work
If the tool refuses or errors, record that as a result and try a smaller task. If every run already meets every criterion, add a harder test input. If you cannot use a tool, start the alternative assignment (iteration audit) with the dated sample log.

## Debrief (3–5)
1. Which of your criteria was hardest to score, and how would you rewrite it? (evaluate)
2. Did any change improve one criterion and break another? How did you notice? (analyze)
3. What did the peer swap reveal that you could not see yourself? (analyze)
4. Which part of your task did you keep on the floor, and why? (evaluate)

## Deliverable and rubric
A3 (Application Assignment, Chapter 5): frame card, at least four versions, test record, peer swap record, verification note, reflection, AI Use Declaration. 10-point rubric in the chapter.

## Accessibility and alternatives
No-device or opt-out route: the iteration audit (alternative assignment) using the provided dated sample log, started in class with the team. Screen-reader-friendly log template (a plain table). The peer swap can be done by sharing text in any accessible format; a student for whom the swap is a barrier uses the alternative's reader test.

## Safety and privacy
No personal or confidential data in prompts. No employer data unless you use the employer's approved tool under its rules. Use a fresh, temporary chat, so earlier chats do not shape the test. Save outputs as text excerpts; crop screenshots.

## Instructor notes
Pair students from different majors for the swap where possible. Collect a few anonymized "most useful change" examples for review in the next concept session. Remind students that v1 is an honest first attempt, not a straw man.

# Lab 6.3 — Two Steps or One?

| Field | Value |
|---|---|
| Type | Compare |
| Objectives | O6 (LO2, LO3) · tags 4D:DEL, 4D:DISC |
| Time | 30 minutes (10-minute version available), at home or in Compass (optional) |
| Materials | Any AI chat tool that can open a fresh, temporary chat; the provided constructed meeting notes with planted errors and the error key (course site; open the key only at step 3); a timer |

## Steps (tool-neutral)
Give yourself the **same time to check** in both versions: 5 minutes.

1. **Version 1, one prompt (8 min).** In a fresh chat, ask for the meeting update email from the notes in one prompt (use the provided prompt). Then check the **final email** against the notes for 5 minutes and correct what you find.
2. **Version 2, a chain (12 min).** In a fresh chat, ask only for a list of decisions and action items, each with an owner and a due date, exactly as written in the notes. Check the **list** against the notes for 5 minutes and correct it. Then, in a fresh chat, ask for the update email from your corrected list.
3. **Count (8 min).** Open the error key. For each planted error, mark whether it reached each final email. For each error that got through, ask: **was it in the notes, or introduced by the output?** Which check position caught more, and why?

Save this for your Failure Diary (Chapter 4): one error that got through.

**10-minute version:** Version 2 only; compare with the dated sample output for Version 1 on the course site.

## Expected observations
Errors that sit in the notes themselves (two lines that give different dates) usually reach the one-prompt email in fluent form, where they are harder to spot in 5 minutes. In the short list, most are easier to see. Errors that the output introduces (a task given the wrong owner) can appear in either version; the check catches them only if you compare against the notes, not against your memory of the meeting.

## If it does not work
If both checks catch every error, the position of the check does not matter for this input; that is a valid result. Try the harder notes file (version B on the course site).

## Debrief (3–5)
1. Which errors did each check catch, and were they in the notes or introduced by the output? (analyze)
2. Where else could the check go, and would it catch more or fewer errors? (evaluate)
3. When would one prompt with a final check have been good enough? (evaluate)
4. In this chain, who decided the steps? How would that differ in an agent (Chapter 14)? (understand)

## Deliverable and rubric
The count table and two sentences on where your check belongs. Ungraded; can become the workflow card in your library.

## Accessibility and alternatives
No-device route: dated sample outputs (model name and date) for both versions on the course site; do the checks and step 3 on paper. Plain-text notes and key for screen readers.

## Safety and privacy
Use only the provided notes; they are constructed, with roles instead of names. When you build chains for your own notes, replace people's names and contact details before pasting (Chapter 15).

## Instructor notes
The key lists five planted errors in the notes: two lines that give different due dates for one task, one task with two owners, one decision recorded as "postponed" and then "approved", and one meeting time without a time zone. Ask students to separate errors that were in the notes from errors the output introduced.

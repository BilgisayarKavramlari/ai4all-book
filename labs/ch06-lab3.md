# Lab 6.3 — Two Steps or One?

| Field | Value |
|---|---|
| Type | Compare |
| Objectives | O6 (LO2, LO3) · tags 4D:DEL, 4D:DISC |
| Time | 25 minutes, at home or in Compass (optional) |
| Materials | Any AI chat tool that can open a fresh, temporary chat; the provided constructed meeting notes with planted errors and the planted-error key (eLearning; open the key only at step 4) |

## Steps (tool-neutral)
1. **One prompt (5 min).** In a fresh chat, ask for the meeting update email from the notes in one prompt (use the provided prompt). Save the output.
2. **Step 1 of the chain (5 min).** In a fresh chat, ask only for a list of decisions and action items, each with an owner and a due date, exactly as written in the notes.
3. **Your check, then Step 2 (8 min).** Compare the list line by line with the notes. Correct anything wrong. Then, in a fresh chat, ask for the update email from your corrected list. Save the output.
4. **Count (7 min).** Open the planted-error key. For each planted error, mark whether it reached the one-prompt email and the chain email. If an error slipped through both, note what kind of error it was; Chapter 4 calls a lost detail of this kind *context loss*. Save it for your Failure Diary (Chapter 4).

[COMPASS: ch06-lab3 — notes, prompts and key]

## Expected observations
Planted errors that sit in the notes themselves (a date that conflicts with another line) usually reach the one-prompt email in fluent form. In the chain, they are easier to spot in the short list, so most are corrected at the check. Errors you do not know to look for can still slip through both.

## If it does not work
If both versions catch every error, the check is not adding anything for this input; that is a valid result. Try the harder notes file (version B on eLearning).

## Debrief (3–5)
1. Which errors did your check catch, and how long did the check take? (analyze)
2. Where else could the check go, and would it catch more or fewer errors? (evaluate)
3. When would one prompt have been good enough? (evaluate)
4. In this chain, who decided the steps? How would that differ in an agent (Chapter 14)? (understand)

## Deliverable and rubric
The count table and two sentences on where your check belongs. Ungraded; can become the workflow card in your library.

## Accessibility and alternatives
No-device route: dated sample outputs for both versions on eLearning; do steps 3 and 4 on paper. Plain-text notes and key for screen readers.

## Safety and privacy
Use only the provided notes; they are constructed, with roles instead of names. When you build chains for your own notes, replace people's names and contact details before pasting (Chapter 15).

## Instructor notes
The key lists five planted errors: two date conflicts, one task with two owners, one decision recorded as "postponed" and then "approved", and one meeting time in the wrong time zone. Most students catch the first three at the check.

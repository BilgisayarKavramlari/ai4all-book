# Lab 21.3 — How a Code Aged

| Field | Value |
|---|---|
| Type | Explore (optional, at home) |
| Objectives | Ch. 21 O4 (LO7) · tags 4D:DIL |
| Time | 20–25 minutes |
| Materials | The provided excerpt sheet (instructor package): one principle from the ACM code's 1992 version and its counterpart in the 2018 version, for privacy or for competence, each with its source (ACM's own pages), short excerpts only |

## Steps (tool-neutral)
1. Choose privacy or competence. Read both versions of the principle on the sheet.
2. List what the 2018 version adds and what it drops or narrows.
3. For one addition, write one sentence on what it suggests the field learned between 1992 and 2018. Mark it as your inference.
4. Name one event in the world between 1992 and 2018 that could have prompted the change (for example, a kind of system that did not exist in 1992). Then write one review trigger for your own code of the same kind: an event that would send you back to a line, such as "a new kind of tool at my job."

## Expected observations
The 2018 code names machine-learning systems and asks that systems whose future risks cannot be reliably predicted be reassessed often in use (principle 2.5); students comparing the two versions usually find that the newer text says more about systems changing after release. Exact wording differences depend on the excerpts provided; use only what the sheet shows.

## Debrief
1. Which change surprised you, and what does it suggest about how fast codes age? (evaluate)
2. Which review trigger did you add to your own code? (apply)

## Deliverable and rubric
None (optional practice).

## Accessibility and alternatives
The excerpt sheet is available as an accessible document. Students may instead compare two dated versions of any written rule they know (a course policy, a club's rules, a workplace handbook) and do steps 2–4 on those.

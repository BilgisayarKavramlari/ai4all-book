# Lab 6.2 — Context A/B

| Field | Value |
|---|---|
| Type | Compare |
| Objectives | O2, O3 (LO2, LO3) · tags 4D:DESC, 4D:DISC |
| Time | 40 minutes (10-minute version available), at home or in Compass (optional) |
| Materials | Any AI chat tool that can open a fresh, temporary chat; the provided document (a constructed 12-page store policy with shipping, returns, warranty and gift-card sections, dated), three provided questions with answer keys, and two provided in-context examples (eLearning); a scoring sheet |

## Steps (tool-neutral)
The three questions are labeled as test inputs (Chapter 5): question 1 is **typical** (its answer is in one short, clear section); question 2 is **different** (it needs two sections); question 3 is the **edge** input (its answer sits in the middle of the document, in a footnote).

1. **Version (a), no document (8 min).** Ask each question in a fresh chat with no document. Score each answer against its key: correct, partly correct, wrong.
2. **Version (b), whole document (8 min).** Paste the whole document, then the question. Score.
3. **Version (c), selected and labeled (10 min).** For each question, paste only the section(s) it needs, each with a label and the document's date, a gap instruction ("If the answer is not in the material, say so"), and the full task last. Score.
4. **With and without examples (10 min).** Add the two provided in-context examples (a sample question with a model answer that quotes the policy) to version (c). Run the three questions again and score. Do the examples help, hurt or make no difference?
5. **Conclude (4 min).** Write a conclusion limited to your test: "For these three questions, with [tool and model] on [date], …"

**10-minute version:** question 1 only, versions (a) and (c).

[COMPASS: ch06-lab2 — document, questions, keys, examples and scoring sheet]

## Expected observations
Version (a) often gives confident general answers that do not match this store's policy. Version (b) is usually better but can mix up sections (for example, warranty rules applied to returns). Version (c) usually matches the keys most often. The effect of examples varies by tool and question; "no difference" is a valid result.

## If it does not work
If all versions score the same, your tool may handle this short document well; note it as a result, and look closely at question 3. If a tool cannot open files, paste the text.

## Debrief (3–5)
1. Which version matched the keys most often, and why do you think so? (analyze)
2. Did any answer in version (b) mix information from the wrong section? (analyze)
3. Would you keep the in-context examples for this task? What evidence decided it? (evaluate)
4. What would change in your conclusion if you tested ten questions instead of three? (evaluate)

## Deliverable and rubric
Scoring sheet and a three-sentence conclusion. Ungraded; can support a library entry's "In-context examples: used / not used" field.

## Accessibility and alternatives
No-device route: dated sample outputs (model name and date) for all versions on eLearning; score them against the keys. Screen-reader-friendly plain-text versions of the document and scoring sheet.

## Safety and privacy
Use only the provided document; it is constructed and contains no real customer data. Fresh, temporary chats for each version.

## Instructor notes
Question 3's answer sits in the middle of the document on purpose (Chapter 3, "lost in the middle"). Collect results across students: the spread itself is a lesson about testing on more than one run and one tool.

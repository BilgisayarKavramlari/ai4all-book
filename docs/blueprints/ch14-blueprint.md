| M2 | "If each step works 95% of the time, a 20-step run works about 95% of the time." | 14.3 (under the chapter's stated assumptions, 0.95^20 ≈ 36%; prediction box first); τ-bench and METR evidence (14.3); Deep 14.B for the model's limits. **Refutation check:** must not create "long agent runs always fail" — checks, retries and better steps change the result (F14.8), and real errors are not independent |

## 5. Concept sequence

**Session question, answered in the Summary:** *When an AI system can take actions on its own, where do people belong in the work?* Answer (hedged): first decide whether you need an agent at all; a fixed workflow is simpler and easier to check. If you do, people belong before every action that cannot be undone or whose error other people would bear (approval gates the system enforces), between steps where an error would be cheap to fix (check points), and at the conditions under which the run must stop and hand back control (stop points). Give each tool only the access its step needs, keep a log the system writes, and test the whole workflow in a dry run, including one planted fault, before anyone relies on it. Errors compound over steps, so a demo that worked once is not evidence that a run will work; and a gate helps only if the person at it can, and does, say no.

New Key Terms (Chapter 6 is the defining chapter; definitions are identical to the chapter text):

| Term | Definition | Türkçe |
|---|---|---|
| Context layers | The separate sources of text that together fill a model's context window in one turn, each set by someone and at some time. | Bağlam katmanları |
| Context engineering | Deciding what goes into a model's context window, from which layer, in what form and in what order, so that a task can be done well. | Bağlam mühendisliği |
| Standing instructions | Instructions you write once, in a tool's settings or a project, that the tool adds to every conversation in that scope. | Kalıcı talimatlar |
| Project space | A workspace in a tool where chosen files and instructions are added to every conversation started inside it. | Proje alanı |
| Prompt template | A prompt written for a recurring task, with fixed parts that stay the same each time and placeholders for the parts that change. | İstem şablonu |
| Placeholder | A marked slot in a template, such as {NOTES} or {DATE}, that you replace with new material each time you use it. | Yer tutucu |
| Prompt version | A numbered, dated state of a prompt or template, recorded with what changed and what it was tested on. | İstem sürümü |
| Prompt library | A personal or shared collection of tested prompt templates, each recorded with when to use it, what it was tested on and how it has changed. | İstem kütüphanesi |
| Prompt chain | A fixed sequence of prompts that you run one after another, where each step's output becomes the next step's input and you check the result between steps. | İstem zinciri |

### Review Questions A
1. System prompt; standing instructions; project files and memory notes; conversation so far; pasted or retrieved text; your prompt. You write your prompt at the moment you send a message.
3. Context engineering is deciding what goes into a model's context window, from which layer, in what form and in what order, so that a task can be done well. Writing one prompt covers only one layer (your prompt); context engineering also covers selected documents, examples, standing instructions, project files, memory and the conversation so far.
5. Select excerpts, not whole documents; name each excerpt's source and date; say what to do when the material is not enough; leave out what must not be shared.
7. **(b)** In-context examples steer the output only while they are in the context; the model's settings do not change (Chapter 3). (a) and (c) are M3; (d) is contradicted by Lu et al. (2022) and Zhao et al. (2021).
9. **(b)** Five in-context examples lowered o1-preview's MedQA score (Nori et al., 2024). (a) describes GPT-4 in 2023, not o1-preview; (c) is wrong: across benchmarks few-shot was inconsistent and on average hurt; (d) is not reported.
11. *Invisibility* (a forgotten standing instruction, such as "answer in under 100 words," spoils an unrelated task); *staleness* (a memory note that is no longer true, such as Sam's co-op); *privacy* (stored notes or files about you or others sit in the provider's systems and reach later chats; Chapter 15).
13. A marked slot in a template that you replace with new material each time you use it, such as `{NOTES}` or `{DATE}`.

### Review Questions B (model answers)
1. *Layers:* standing instructions (a line such as "write formally" or "British spelling") — check the tool's settings; project files or a style guide in a project — check the project; memory notes (for example, that she studied in the UK) — open the memory list; the conversation so far (an earlier turn in British English) — start a fresh chat; pasted text written in British English — check what she pasted; the system prompt — she cannot see it, but a fresh chat with no standing context isolates it. *Method:* change one layer at a time and rerun the same prompt.
3. *Diagnosis:* the three in-context examples are one-sided (all written for A-grade essays), so the outputs lean toward praise, like class imbalance in miniature (section 6.4). *Test:* three test inputs (a typical B essay, a different kind of essay such as a lab report, an edge case such as an essay that misses the prompt), each run with balanced examples (one A, one C, one failing) and with no examples but clear criteria; score each output against two or three criteria (accurate, specific, actionable); keep whichever version meets the criteria more often, and record the test in a library entry.
5. *Chain:* Step 1, extract from each set of notes only the candidate's answers to each fixed question, with quotes; check: the intern (or a recruiter) compares the extraction with the notes, line by line; Step 2, summarize each candidate against the job's written criteria, with no scores; a person assigns any scores. *Why there:* errors in extraction (a misattributed answer) are cheapest to catch before they shape a summary, and scoring people is a decision that should stay with a person. *Never in context:* personal data that is not needed or that the organization's policy forbids sending to an AI tool, such as contact details, protected characteristics or medical information (Chapter 15; bias risk, Chapter 16).

### Review Questions C (scoring guidance)
1. Strong answers use the Case Study: a design that helped GPT-4 in 2023 hurt o1-preview in 2024 (Nori et al., 2024), which argues for libraries *with* versions, dates, model names and test records, so that retesting is quick, not for abandoning them. Accept "agree" if it argues that very short-lived tasks do not repay the effort, provided it addresses the test-record argument.
3. Strong answers say what a published system prompt reveals (tone, formatting and refusal instructions; a dated record of changes; Willison, 2024) and what it does not (training data, model behavior on a given input, standing instructions or memory added for each user). Accept either side with that distinction.

### Spaced Review
1. Everything the model receives in one turn: a system prompt, the conversation so far, pasted or retrieved text and your prompt (plus, in many tools, standing instructions and project or memory text). In a 2023 test, information in the middle of a long input was used less reliably than at the start or end (Liu et al., 2024).
3. The three test inputs may share a feature that makes the template look right for an unrelated reason, for example notes that all happen to list decisions in the same order the template expects. A new kind of input breaks it. Choosing a truly different and an edge input, and retesting on new inputs over time, reduces this risk.
5. Usually placeholders: context (the material) and sometimes in-context examples. Usually fixed: task, role, constraints and output format (and examples, if a test shows they help).

### Case Study Questions
1. *Context (what the model received):* in-context examples chosen by similarity to each question; step-by-step reasoning GPT-4 had written for those examples. *Workflow (how the task was run):* five runs with shuffled answer options and a majority vote.
3. Fields that would have warned: "tested on" (GPT-4, November 2023, MedQA only); "in-context examples: used, and the test that decided" (helped on GPT-4); "when not to use" (other models untested). A 2024 retest on o1-preview with and without examples would have shown the reversal.
5. *Should:* note that the authors work for Microsoft and study OpenAI's models, with an OpenAI co-author in 2024; report results as these authors' benchmark results and look for independent replication. *Should not:* dismiss the findings because of affiliation; the method, data and limits are published and can be checked.
